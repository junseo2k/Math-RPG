## 1. 시각 방향

### 1-1. 확정 [확정]
- 그림체: **픽셀아트**
- 제작 수단: **AI 생성 + 보정** (7장 프롬프트·보정 기준 참고)
- 2D 탑다운(3/4 내려다보기), 시간 테마. 시각 스타일은 **중세풍** (2026-10-19 횡스크롤에서 변경)
- 캐릭터는 **4방향**(아래·위·옆) 스프라이트로 그리고, 반대쪽 옆은 좌우 반전으로 쓴다. 대각선 조준은 가까운 방향 스프라이트를 쓴다. 이동은 8방향 그대로 (2026-10-21 확정)
- 캐릭터가 바라보는 방향은 마우스 조준 방향을 따른다(이동 방향과 다를 수 있음 → 뒷걸음 시 run 역재생은 쓰지 않고 그대로 재생)
- 이집트 신화는 **스토리·서사에만** 쓰고, 시각 요소(배경·UI·캐릭터·이펙트)에는 이집트풍을 넣지 않는다
- 주인공은 몰락한 태양신 본인이다 (GameDesign 2장)

### 1-2. 기준 [확정]
| 항목 | 값 | 이유 |
|---|---|---|
| 기준 해상도 | 640×360 → 1920×1080(3배) | 정수 배율로 픽셀이 깨지지 않음 |
| PPU(Pixels Per Unit) | 32 | 현재 플레이어 충돌체 1×1 유닛 = 32×32px |
| 주인공 프레임 | 48×48px (몸통 약 32×32) | 검 휘두름·회피 잔상 여유 |
| 시종 보스 프레임 | 96×96px (몸통 약 64×64) | 현재 보스 충돌체 2×2 유닛 |
| 팔레트 | 32색 이내 공용 팔레트 | AI 생성물 색 통일 |

- dev 전달: Pixel Perfect Camera 사용 시 카메라 크기는 기준 해상도에 맞춰 조정 필요(현재 카메라 크기 6은 임시).

### 1-3. 색 체계 [확정] + 팔레트 역할 [승인]
| 대상 | 색 | 의미 |
|---|---|---|
| 태양신(주인공), 보상 UI | 금색·백열 | 흐름, 생명 |
| 달의 시종(일반 적·보스) | 은색·차가운 청색 | 불변, 영원한 밤 |
| 밤하늘 | 시간대별로 변화(3장) | 시간 진행 |
| **위험 (예고·실행)** | **빨강 + 백열** — 이 용도 전용 | 배경·캐릭터·UI 장식에 쓰지 않는다 |
| **역행** | **청록** (+ 주인공 금색 가장자리) | 플레이어 시간 권능 |

- **[확정]** 중세 모티브(채식 필사본 테두리, 스테인드글라스, 고딕 아치, 천문 시계, 모래시계, 태양 문장)는 **배경과 UI 장식**에 쓰고, 전투 정보 판독을 방해하지 않게 한다.
- **[승인]** 위험 정보는 색만으로 구분하지 않는다. 예고는 **차오르는 채움(움직임) + 윤곽(형태)**, 실행은 **진한 색 + 백열 번쩍**으로 함께 구분한다 (D2).
- 배경은 채도·명도를 낮춰 캐릭터와 위험 표시보다 한 단계 어둡게 한다 [권장값].

### 1-4. 차별화 기준 [확정] (2026-10-21)
도트 탑다운 액션 참고작(예: 세피리아)과 닮아 보이지 않게, 아래 기준을 지킨다.

| 구분 | 내용 |
|---|---|
| 참고작에서 가져올 것 | 기준 해상도, 캐릭터 크기, 전투 판독성 같은 **기술 기준**만 |
| 가져오지 않을 것 | 색감, 캐릭터 디자인·비율, UI 모양 |
| 참고 방식 | 한 작품만 보지 않고 2~3개를 섞어 본다 |

정체성 요소 (그림 실력보다 연출로 분위기를 만든다):
1. **빛과 어둠**: 영원한 밤이라 전장은 어둡고, 몰락한 태양신 주변만 희미하게 빛난다. 2D 조명(URP 2D Light)으로 처리한다. 위험 표시는 조명과 무관하게 항상 잘 보여야 한다.
2. **시각에 따른 화면 색감**: 3장 하늘 그라데이션을 하늘만이 아니라 전장 전체 색감(조명 색)에도 적용한다.
3. **두 색 축**: 1-3의 금색(태양) / 은청색(달) 대비를 모든 자산에서 지킨다.
4. **시계 모티프**: 적·보스·UI에 시계 바늘, 톱니, 모래시계, 천문 시계 형태를 넣는다 (1-3 중세 모티브와 함께).

## 2. 화면 구성 (시험판 A)

### 2-1. 특성 보상 카드 [승인] (구 "시작 능력 선택" 대체)
- 규칙: 일반 스테이지 클리어 시 통합 풀 3개 중 1개, 보스 클리어 시 역행 전용 3개 중 1개 (CombatDecisions 9장)

| 요소 | 내용 |
|---|---|
| 카드 3장 | 가로 배치. 이름, 종류, 다음 레벨 효과 |
| 종류 구분 | **아이콘 모양 + 글자**: 역행 전용 = 마름모 테두리(`ui_icon_active` 재사용), 공용 = 원형 테두리(`ui_icon_passive` 재사용) |
| 레벨 배지 | 카드 하단 "신규 Lv.1" / "Lv.n → Lv.n+1" (현재 코드가 글자로 표시) |
| 보상 메시지 | 제목 아래 "+50G", "유물 [이름] 획득", "기억 조각 +10" |
| 선택 피드백 [확정] | 호버 시 카드 확대 + 테두리 금색, 선택 시 카드가 빛나며 다른 카드 어두워짐 |

- **[확정]** 카드 크기 기준 해상도 140×200px, 카드 간격 24px, 선택 연출 0.3초.
- `[임시]` 배지는 시험판 A에서 쓰지 않는다 [보류].

### 2-2. 전투 HUD [승인]
| 위치 | 요소 | 현재 구현 | 최종 표현 [권장값] |
|---|---|---|---|
| 좌상단 | 플레이어 HP (100) + 숫자 | 금색 바 + "76 / 100" | 태양 문장 끝장식이 달린 바 테두리 |
| HP 바 위 | 보호막 | 정보 줄에 "보호막 N" | HP 바 위에 겹치는 은빛 덧바 |
| 좌상단 아래 | 정보 줄: G, 기억 조각, 포션[Q], 역행[S], 보호막 | 글자 한 줄 | 아이콘 16×16 + 숫자로 분리 |
| 그 아래 | 회피 재사용 게이지 | 금색 바 | 회피 아이콘이 차오름, 준비 시 반짝 |
| 역행 아이콘 | 역행 쿨타임 | 글자 "준비 / N초" | 청록 나선 시계 아이콘이 차오름, 준비 시 금색 반짝, 사용 불가 시 흔들림 |
| 상단 중앙 | 시각 · 며칠째 [확정] | 천문 시계 + 글자 | 그대로 |
| 상단 중앙 아래 | 스테이지 진행 | 3칸 (일반 2 = 작은 사각, 보스 = 마름모) | 모양 구분 유지 [확정] |
| 하단 중앙 | 보스 HP · 이름 | 바 + 이름 | 은청색 테두리 바 |

- HUD는 화면 가장자리에만 두어 전투 영역을 가리지 않는다 [확정].
- 보스 머리 위 권능 게이지(축적 스택) [보류].

## 3. 시간 진행 시각화

| 요소 | 내용 |
|---|---|
| 하늘 그라데이션 [확정] | 18:00 노을(주황·보라) → 19:00 → 20:00 → 21:00 남색. **시험판 A는 보스 1명이라 18:00 → 19:00 2단계만 쓴다** |
| 시계 UI [확정] | 중세 천문 시계 모양, 태양 바늘. 1시간 = 바늘 한 칸 |
| 시각 전진 연출 [확정] | 보스 처치 시 시계 바늘이 돌고 "+1시간", 하늘색 전환 1.0초 |
| 본편 하늘 흐름 [확정] | 자정(6번째 보스)까지 점점 어두워지고, 자정 이후 점점 밝아져 06:00 새벽 (GameDesign 16-4) |
| 장 전환 [확정] | 장 마지막 보스(3·6·9·12번째) 처치 시 더 큰 연출. 자정은 종 12번 (GameDesign 16-4) |
| 06:00 연결 [확정] | 바늘이 06:00을 지나며 18:00으로 이어지는 고리 연출(본편, 시험판 미도달) |

- 규칙: 시간은 보스 처치마다 1시간 전진(확정). 일반 방 클리어로는 시각 변화 없음.

## 4. 시간 권능 시각 구분

- 원칙: 권능마다 **형태 · 움직임 · 색** 세 가지를 함께 정한다. 색만으로 구분하지 않는다.
- 아래는 **모티브 언어**이며, 패턴이 미결인 권능의 구체 이펙트는 정하지 않는다.

| 대상 | 권능 | 형태 | 움직임 | 색 | 범위 |
|---|---|---|---|---|---|
| **플레이어** | **역행** [승인 D4] | 반시계 나선, 거꾸로 흐르는 잔상 | 나선이 플레이어 중심으로 거꾸로 감김 → 복원 | **청록 + 금색 가장자리** | **시험판 A** |
| 플레이어 | 정지 | 금 간 유리 프레임 | 완전 정지, 채도 제거 | 흰색·회색 | 시험판 B |
| 플레이어 | 가속 | 날카로운 속도선 | 빠른 점멸 | 주황·적색 계열(위험 빨강과 구분되는 주황) | 시험판 B |

이전 문서의 보스 권능 모티브 [확정, 본편용]. 보스별 권능 배정은 GameDesign에서 미결:

| 장 | 권능 | 형태 | 움직임 | 색 |
|---|---|---|---|---|
| 1 | 축적 | 차오르는 동심원 고리 | 단계적으로 겹쳐 커짐 → 한 번에 터짐 | 금색 → 백열 |
| 1 | 유예 | 공중에 멈춘 모래알, 점선 윤곽 | 멈춤 → 늦게 발동 | 호박색 |
| 1 | 역행 | 반시계 나선, 거꾸로 흐르는 잔상 | 잔상이 역재생 | 청록 |
| 2 | 감속 | 늘어지는 잔상 | 느린 파동 | 남색 |
| 2 | 공유 | 두 대상을 잇는 사슬 | 연결선 맥동 | 보라 |
| 2 | 정지 | 금 간 유리 프레임 | 완전 정지, 채도 제거 | 흰색·회색 |
| 3 | 침식 | 부서져 흩어지는 모래 | 가장자리부터 갉아먹음 | 황토 |
| 3 | 갱신 | 돋아나는 싹, 원형 재생 | 되살아나는 빛 | 녹색 |
| 3 | 가속 | 날카로운 속도선 | 빠른 점멸 | 주황·적색 |
| 4 | 분기 | 갈라지는 반투명 분신 | 여러 경로로 퍼짐 | 은색 |
| 4 | 예지 | 먼저 그려지는 유령 윤곽 | 실루엣이 앞서 이동 | 시안 |
| 4 | 순서(인과 역전) | 뒤바뀐 원인·결과 표식(채식 문자 번호) | 결과가 먼저 나타나고 원인이 뒤따름 | 흑색·금색 |

- 플레이어 역행(청록)과 본편 보스 역행(청록)이 겹친다. 본편 보스 역행을 만들 때 구분 방법을 다시 정한다 [미결].

### 4-1. 축적 보스 이펙트 [보류]
| 상황 | 표현 |
|---|---|
| 축적 스택 | 머리 위 게이지 → 최종: 고리 5개가 차오름 |
| 방출 예고 1.0초 | 최종: 고리가 백열하며 진동 |
| 충격파 | 최종: 금빛 링이 퍼지는 4~6프레임 |
| 탈진 2.0초 | 최종: 웅크린 자세 + 모래가 흘러내림 |
| 돌진 예비 0.4초 | 최종: 몸을 낮추는 자세 + 발밑 먼지 |

### 4-2. 시험판 보스 이펙트 [승인]
- 보스 외형: "달의 시종(가칭)". 보스 정체가 미결(VerticalSliceA M-4)이라 **외형은 확정하지 않는다** (D1). 요구사항만 둔다:
  - 96×96 프레임, 은청색 계열, 패턴마다 **서로 다른 예비 자세 4종**(실루엣만으로 패턴 구분)
  - 예고 중 몸 색은 코드가 주황, 실행 중 빨강으로 덧칠한다 → 그림은 **명도 차이가 큰 은청색**으로 그려 덧칠 후에도 형태가 보이게
- 공통 규칙 (D2):
  - **예고**: 옅은 빨강 윤곽(`fx_boss_zone`) + 실행 순간에 꽉 차는 채움(`fx_boss_fill`)
  - **실행**: 진한 빨강 범위 + 실행 순간 **백열 번쩍**(`fx_hit` 확대 재사용 권장, dev 연결 필요)
  - 판정 범위와 표시 범위는 같은 계산을 쓴다 (코드). 그림은 범위를 넘거나 모자라게 그리지 않는다

| 패턴 | 판정 크기 (유닛) | 예고 표시 | 실행 표시 | 보스 예비 자세 [권장값] |
|---|---|---|---|---|
| 내려베기 | 앞 3×2 | 보스 앞 상자 윤곽 + 채움 | 상자 진한 빨강 + 검 궤적(`fx_sword_arc` 확대) | 검을 머리 위로 치켜듦 |
| 돌진 | 보스 몸 2×2가 벽까지 이동 | 벽까지 이어진 경로 윤곽 + 채움 | 경로 표시 없음, 보스 몸이 판정(빨강 덧칠) + 잔상 | 몸을 낮추고 한쪽 발을 뒤로 |
| 탄막 3연발 | 탄 지름 0.6 | 플레이어를 향하는 조준선(`fx_boss_aim`), 탄이 남아 있는 동안 계속 따라감 | 발사 순간 조준선 빨강 0.1초, 탄(`fx_boss_shot`) | 손을 앞으로 뻗어 달빛을 모음 |
| 낙하 광역 | 지점 3곳, 각 폭 2 × 높이 2 | 지면 윤곽 + 채움 (착지 순간 꽉 참) | 떨어지는 동안 주황, **착지 0.2초만** 진한 빨강. 바위(`fx_boss_rock`) | 두 팔을 하늘로 |

- 특성 "반복되는 운명": 다시 겪는 공격은 실행 색이 일찍 켜진다 (코드). 별도 그림 없음.

## 5. 공통 피드백 · 역행 · 사망과 순환

### 5-1. 공통 피드백
| 상황 | 표현 | 길이 | 상태 |
|---|---|---|---|
| 검 공격 | 금색 호 궤적 3프레임 (`fx_sword_arc`) | 0.1초 | [확정] 표현, 연결은 dev |
| 검 판정 범위 | 휘두를 때 실제 판정 상자 반투명 (`fx_sword_range`) | 0.1초 | [승인] 구현됨 |
| 적·보스 피격 | 흰색 번쩍 (코드 `HitFlash`, 그림 불필요) | 0.1초 | [승인] 구현됨 |
| 플레이어 피격 | **빨간 번쩍** + 화면 흔들림 약 + 무적 동안 **반투명 깜빡임** | 무적 0.8초 [임시] 동안 | [승인 D3] dev 작업 필요 (현재는 흰색 번쩍만) |

| 위험 예고·실행 | 4-2 공통 규칙 | 패턴별 | [승인 D2] |

### 5-2. 사망 → 순환 [확정 연출, 흐름은 승인]
총 2.0초 = 순환 대기. 이후 **영구 성장 화면**(2-5)으로 이어진다.

| 구간 | 연출 |
|---|---|
| 0.0~0.4초 | 주인공의 빛이 꺼지며 쓰러짐 |
| 0.4~1.0초 | 화면 암전 |
| 1.0~1.6초 | 검은 화면에 "N일째 18:00" |
| 1.6~2.0초 | 지평선에서 태양이 떠오름 → 영구 성장 화면 |

- 의도: 되감기가 아니라 "다음 순환"임을 보여준다(사망 ≠ 시간 역행). 역행(5-3, 청록)과 색·방향으로 구분한다: 순환 = 금색·위로 떠오름.

### 5-3. 역행 발동·복원 연출 [승인 D4, 수치는 권장값]
규칙: 즉시 복원 → 0.3초 정지 연출 → 재개 후 0.2초 무적 (CombatDecisions 4·5장)

| 구간 | 연출 |
|---|---|
| 입력 순간 | 플레이어 중심에서 청록 반시계 나선(`fx_rewind_spiral`)이 퍼짐, 가장자리 금색 |
| 정지 0.3초 | 화면 채도 낮춤 + 청록 테두리 비네트(`fx_rewind_screen`). 복원된 보스 예고 표시는 그대로 보인다(판단 시간) |
| 재개 후 무적 0.2초 | 주인공 금색 외곽선 반짝 |
| 사용 불가 (쿨타임 등) | HUD 역행 아이콘 흔들림 (그림 없이 코드) |

- 모두 dev 연결 필요 (현재 코드에 그림 연결 자리 없음).

## 7. AI 생성 + 보정 기준

### 7-1. 프롬프트 공통 틀 [확정]
```
pixel art, {크기}px sprite sheet, top-down 3/4 view, {방향: facing down / facing up / facing right},
medieval dark fantasy, {대상 설명}, {상태 목록},
limited palette, transparent background, no anti-aliasing, crisp pixels
```
- 예(주인공): `fallen sun deity in worn knightly garb, longsword, golden sun emblem, faint halo` + `idle, run, attack, dash, hurt, death` (방향마다 1장씩)

### 7-2. 보정 체크리스트
- 크기를 정확한 픽셀 격자로 다시 맞춤(흐린 픽셀·안티앨리어싱 제거)
- 공용 팔레트로 색 감소
- 프레임 간 위치·크기 정렬(피벗 일치)
- 배경 완전 투명 확인
- **[승인]** 코드가 늘리는 이펙트(`fx_boss_zone/fill/aim`, `fx_sword_range`)는 늘어나도 깨지지 않게 단색 + 1px 테두리 또는 반복 무늬로 보정
- 실제로 보정을 마치지 않은 이미지는 완성 자산으로 보고하지 않는다.

- **[미결]** 사용할 AI 생성 도구와 상업적 이용 조건(확인 전 단정하지 않음)

## 8. 전달 사항

**dev에게**
- 자산 이름 규칙 [확정]: `chr_player_{상태}`, `boss_{이름}_{상태}`, `enemy_{이름}_{상태}`, `fx_{이름}`, `ui_{이름}`. 시험판 보스는 코드상 `boss_slice_{상태}`
- 스프라이트 Import: Point 필터, 압축 없음, PPU 32
- 그림을 넣기 전에 필요한 코드 작업:
  1. `fx_boss_*`, `fx_sword_range`는 1프레임만 쓰고 판정 크기로 가로·세로를 따로 늘린다 → 늘어나도 픽셀이 깨지지 않게 "타일 반복 그리기(Tiled/Sliced)"로 바꾸는 것을 권장. `fx_boss_shot`은 0.6유닛(약 19px)으로 줄어 픽셀이 고르지 않을 수 있음
  2. 시험판 보스는 공격 애니메이션을 재생하지 않는다(방향 전환만) → 단계·패턴별 `boss_slice_*` 재생 연결
  3. 보스·일반 적은 HP 0에서 바로 사라지거나 비활성화된다 → 사망 애니메이션을 쓰려면 연출 시간 확보 필요
  4. 플레이어·적 스프라이트를 4방향(`_down`, `_up`, `_side`)으로 고르는 코드 필요 (현재는 좌우 반전만). 방향은 플레이어 = 마우스 조준, 적 = 이동·공격 방향
  5. 역행 연출(5-3), 플레이어 빨간 피격·무적 깜빡임(5-1 D3), 보스 실행 백열 번쩍(4-2 D2), 검 궤적·회피 잔상 연결
  6. 상점 통로(`obj_shop_passage`), 상점·성장 화면(임시 IMGUI → 기존 카드 UI 방식), HUD 아이콘 연결
- 코드가 이미 자동으로 쓰는 이름(그림만 넣으면 교체): `chr_player_*`, `enemy_sentinel_*`, `boss_slice_idle`, `fx_boss_zone/fill/aim/rock/shot`, `fx_sword_range`, `tile_ground_ch1`(바닥), `obj_exit_{locked,open}`, `ui_card`, `ui_icon_{active,passive}`, `ui_clock_{face,hand}`, `ui_stage_{room,boss}`

**planner에게**
- 시험판 보스 정체·외형 확정 필요 (D1, VerticalSliceA M-4)
- 본편 보스 역행과 플레이어 역행의 시각 구분 (4장 미결)
