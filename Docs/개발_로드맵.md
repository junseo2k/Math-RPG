## 0. 순서를 이렇게 잡은 이유

기획서 5-7과 CLAUDE.md 1장이 **"전투/타격감이 수학 문제보다 우선순위가 높다"**고 명시하고, 특히 기획서 5-7은 검증 조건을 이렇게 못 박았습니다:

> 프로토타입 단계에서부터 **문제 로직 없이 순수 액션(평타-스킬-회피 루프)만으로도 재미가 검증되어야 함.**

따라서 이 로드맵은 **문제 시스템을 M3까지 의도적으로 미룹니다.** 액션이 재미없는데 문제를 얹으면 "재미없는 액션 + 공부"가 되고, 이건 이 프로젝트가 가장 피해야 할 결과입니다. M1은 그래서 단순한 마일스톤이 아니라 **게이트**입니다 — 통과 못 하면 M2로 넘어가지 않고 M1을 다시 만듭니다.

데이터 구조(개념 트리·단원표·시너지 콤보)를 M4로 미룬 것도 같은 맥락입니다. 이 셋은 공통 ID 체계로 서로를 참조해야 하는데(CLAUDE.md 4-4), 전투에서 개념이 실제로 어떻게 쓰이는지 M3에서 확인한 뒤에 설계해야 ID 체계를 두 번 갈아엎지 않습니다.

## M2 — 마나 · 스킬 2계층 & 숙련도 골격 (문제는 아직 없음)

> **2026-08-24 재정의.** 개정 기획서 5-1이 스킬을 **평타급 / 큰 스킬 2계층**으로 나눴고, 숙련도·스킬 숙련도 던전이 신설됐다. 그에 맞춰 다시 씀.
> **마나는 유지된다** — 개정 기획서 본문에는 마나가 등장하지 않지만, 2026-08-24 사용자 확정으로 **마나가 1차 페널티 자원**으로 존속한다 (CLAUDE.md 3장). 기획서만 읽고 이 항목을 지우지 말 것.

**목표:** 스킬의 **연출 · 계층 구조 · 자원 흐름**을 먼저 완성한다. 문제 UI는 M3에서 끼워 넣는다.

- [ ] `Combat/` — **마나 자원**, 소모/회복. 큰 스킬 발동 시 소모
- [ ] **스킬 2계층 구분** (기획서 5-1) — `평타급 스킬`(문제 없이 즉시 발동, 마나 소모 없음) / `큰 스킬`(마나 소모 + M3부터 문제 등장). 이 단계에서는 큰 스킬도 문제를 건너뛰고 즉시 발동
- [ ] 스킬 발동 파이프라인 — 입력 → 마나·쿨다운 검사 → `AttackTimeline` 재생 → 히트 판정. M1의 평타 파이프라인을 일반화
- [ ] 스킬 3종 시제품 (검 계열 2 + 마법 계열 1) — 이펙트와 **차징감(예열 프레임)** 위주
- [ ] **숙련도 골격** (기획서 5-1) — 큰 스킬 사용 횟수를 누적하고, 일정 단계에서 "문제 없이 즉시 발동"으로 전환되는 상태 기계. 실제 난이도 하락·마나 소모 감소는 문제가 생기는 M3에서 연결
- [ ] **마나 고갈 → 평타 + 평타급 스킬 전용 상태** (기획서 5-6 노룩 클리어의 구조적 근거)
- [ ] `Data/SkillData` ScriptableObject — 계층 구분, 기본 마나 소모량, 오답 시 추가 소모 배수, 쿨다운, 데미지 배율, 숙련도 단계별 임계값을 **전부 인스펙터 노출** (미정 수치)

**완료 기준:** 스킬 3종이 계층 구분에 따라 마나를 소모하며 발동되고, 마나가 바닥나면 평타 + 평타급 스킬만 가능한 상태로 전환된다. 큰 스킬 반복 사용 시 숙련도 단계가 오르는 것이 로그로 확인된다.

**하지 말 것:**
- 계산기 특수기능 사용 횟수 카운터·**계산기 게이지**를 만들지 마세요 — 둘 다 폐지됐습니다 (기획서 6-1, 2026-08-24 확정).
- 마나와 계산기를 **하나의 자원으로 합치지 마세요.** 계산기는 무제한이고 마나는 유한한 별개 자원입니다.
- "평타급 vs 큰 스킬"의 구체적 경계 수치(데미지 배율 등)는 **미정**이므로 임의로 정하지 말고 인스펙터 노출만 해두세요.
- **확률·통계 관련 스킬을 만들지 마세요** — 마법 계열은 도형만 남기는 것으로 확정됐습니다.

## M3 — 수학 문제 시스템 연결

**목표:** M2의 스킬 파이프라인에 문제 단계를 끼워 넣는다. **전투 리듬을 죽이지 않는 것**이 성공 조건.

> **2026-08-24 문제 구조 확정** — 기획서 5-3의 "단계별 스캐폴딩 + 오답 소거"는 **둘 다 폐지**됐다. 문제는 **최종 답만 묻는 단일 질문 객관식**이고, "어떤 개념을 쓸까"라는 판단은 객관식으로 묻지 않고 **플레이어가 계산기 특수기능 버튼을 고르는 행위**로 드러난다.

- [ ] `Data/ProblemData` — **단일 질문 + 객관식 보기** 구조. 스캐폴딩 단계 배열이 아님

**문제 설계 최상위 원칙 — 기획서 5-3-1 (신규):**

- **스캐폴딩 단계 배열이나 오답 소거 로직을 만드는 것** — 둘 다 폐지됐습니다 (2026-08-24).

## M6 — 계산기 시스템

> **2026-08-24 재작성.** 개정 기획서 6장에서 **3계층 구조가 2계층으로 개편**되고 **사용 횟수 제한이 폐지**됐다. 대신 **블록 입력 UI(6-5)**가 이 마일스톤의 가장 큰 작업이 됐다.

**목표:** 기획서 6장의 개편된 구조 구현. 핵심은 "무제한이지만 조작이 개념 판단을 요구하는" 계산기.

- [ ] **기본 계산기** — 사칙연산 + 특수 기능이 **전부 여기 포함**. 스토리 진행에 따라 순차 해금되고, **해금 후에는 무제한 사용** (기획서 6-1)
- [ ] 특수 기능 — 근의공식 / 지수·로그 / 급수 / 미분(단일 해금형), 인수분해 · 삼각함수(티어형) (기획서 6-2)
- [ ] **블록 입력 UI** (기획서 6-5) — 이 마일스톤의 핵심
  - 타이핑 없이 **선택/클릭/블록 배치만으로** 완결. 전투 중 물리 키보드 숫자 입력은 배제
  - 블록 2종: **숫자 블록** / **항·식 블록**(`x`, `x+3`, `2x²` 등 문제의 항을 조각내어 제공)
  - 특수 기능은 조합된 입력에 **기능 버튼 원터치**로 결과 획득
  - **되돌리기**("처음으로" / "1단계 취소") 항상 제공 — 페널티와 무관한 조작 편의
  - **유효성 검증 2단계:** ① 문법적으로 불가능한 조합 → 실행 차단 + **오답 처리 포함** ② 문법적으로는 가능하나 정답 경로가 아님 → 실행되지만 **오답 처리**
- [ ] **스킬 숙련도 던전** (구 "계산기 던전", 기획서 6-1) — 큰 스킬 숙련도 집중 파밍용 선택 콘텐츠. 본편과 동일한 전투 시스템 사용
- [ ] **계산기 화살** (기획서 5-8, 선택 요소) — 특수 키로 룬 장갑에서 발사 → 명중 시 문제 → 정답 시 몬스터에 디버프. **안 써도 전투 진행에 지장 없어야 함**. 5-2 상성과는 병행(대체 아님)

**완료 기준:** 블록만 배치해서 특수 기능으로 문제를 풀 수 있고, 잘못된 블록 조합이 두 단계 검증에 따라 각각 다르게 처리된다.

**하지 말 것:**
- **계산 "과정"을 블록으로 단계별 노출하지 마세요.** 과정을 유추할 수 있는 UI는 그 자체가 힌트가 되어 개념 판단 문제(5-3-1)의 긴장감을 죽입니다. 계산기는 **블랙박스형 실행 도구**로 유지.
- 사용 횟수 카운터·리필 로직을 만들지 마세요 — 폐지됐습니다.
- 마나 UI를 만들지 마세요 — 마나 자체가 없습니다.
