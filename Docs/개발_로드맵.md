## 0. 순서를 이렇게 잡은 이유

기획서 5-7과 CLAUDE.md 1장이 **"전투/타격감이 수학 문제보다 우선순위가 높다"**고 명시하고, 특히 기획서 5-7은 검증 조건을 이렇게 못 박았습니다:

> 프로토타입 단계에서부터 **문제 로직 없이 순수 액션(평타-스킬-회피 루프)만으로도 재미가 검증되어야 함.**

따라서 이 로드맵은 **문제 시스템을 M3까지 의도적으로 미룹니다.** 액션이 재미없는데 문제를 얹으면 "재미없는 액션 + 공부"가 되고, 이건 이 프로젝트가 가장 피해야 할 결과입니다. M1은 그래서 단순한 마일스톤이 아니라 **게이트**입니다 — 통과 못 하면 M2로 넘어가지 않고 M1을 다시 만듭니다.

데이터 구조(개념 트리·단원표·시너지 콤보)를 M4로 미룬 것도 같은 맥락입니다. 이 셋은 공통 ID 체계로 서로를 참조해야 하는데(CLAUDE.md 4-4), 전투에서 개념이 실제로 어떻게 쓰이는지 M3에서 확인한 뒤에 설계해야 ID 체계를 두 번 갈아엎지 않습니다.

## M1 — 액션 프로토타입 ★게이트★

**목표:** 수학 문제가 **전혀 없는 상태로** 전투가 재미있는지 검증한다. (기획서 5-7)

### M1-A. 평타 루프
- [ ] 공격 히트박스 / 피격 판정
- [ ] 3타 콤보, 입력 선행(버퍼) 처리
- [ ] 애니메이션 캔슬 타이밍 — 조작이 굼뜨지 않게

### M1-B. 타격감 레이어 (기획서 5-7 핵심 요소)
- [ ] **히트스톱** — 타격 순간 프레임 정지
- [ ] **사운드 레이어링** — 타격음 + 임팩트음 + 환경음 3중
- [ ] **파티클** — 과장된 타이밍
- [ ] **차징감** — 스킬 발동 전 예열 프레임
- [ ] 화면 흔들림, 넉백, 히트 플래시

### M1-C. 회피
- [ ] 숙이기 / 점프 2종 (기획서 5-1)
- [ ] 무적 프레임 — 프레임 수는 `[SerializeField]`로 노출 (기획서 7장 미정 항목)

### M1-D. 더미 적
- [ ] **명확한 텔레그래프(전조 동작)** — 회피가 "반사"가 아니라 "판단"으로 느껴져야 함 (기획서 5-7)
- [ ] 공격 패턴 1~2종, 전부 회피로 극복 가능

**완료 기준 (게이트):**

이 판정은 개발자 본인의 플레이 체감으로 내립니다. **"아니오"면 M2로 진행하지 않고 M1-B(타격감 레이어)를 다시 손봅니다.** 여기서 타협하면 이후 모든 마일스톤이 재미없는 코어 위에 쌓입니다.

**목표:** 스킬의 **연출과 자원 흐름**을 먼저 완성한다. 문제 UI는 M3에서 끼워 넣는다.

- [ ] `Combat/` — 마나 자원, 소모/회복
- [ ] 스킬 발동 파이프라인 — 이 단계에서는 문제를 건너뛰고 **즉시 발동**
- [ ] 스킬 3종 시제품 (검 계열 2 + 마법 계열 1) — 이펙트와 차징감 위주
- [ ] **마나 고갈 → 평타 전용 상태** (기획서 5-1-1, 5-6)

**주의:** 마나와 계산기 특수 기능은 **별개 자원**입니다 (기획서 5-1-1). 이 단계에서 하나의 자원 클래스로 합치지 마세요 — M6에서 분리하려면 훨씬 비쌉니다.

## M3 — 수학 문제 시스템 연결

**목표:** M2의 스킬 파이프라인에 문제 단계를 끼워 넣는다. **전투 리듬을 죽이지 않는 것**이 성공 조건.

- [ ] `Data/ProblemData` — 스캐폴딩 **단계 배열** 구조 (기획서 5-3: "먼저 뭘 해야 할까?" → "값은?" → "최종 답은?")
- [ ] 객관식 보기 + **오답 소거** — 틀릴 때마다 명백한 오답 제거
- [ ] 보기 구성 시 "전형적 실수 패턴"을 오답으로 배치할 수 있는 필드 (기획서 5-3, 학습 진단용)
- [ ] 스킬 발동 → 문제 UI → 채점 → **정답: 마나 적게 소모 + 발동 / 오답: 마나 많이 소모 + 발동 실패**
- [ ] 단계별 오답 페널티 차등 — 초반 판단 단계는 약하게, 최종 계산 단계는 크게 (기획서 5-4)
- [ ] 정령 힌트 **기본형만** — 짧은 대사 + 보기 축소, **상호작용 없음** (기획서 2-4)

**완료 기준:** 문제 UI가 떴다 사라지는 동안 M1에서 검증한 전투 리듬이 유지되는가. 끊긴다고 느껴지면 UI 연출(등장 속도, 시간 정지 여부)을 조정한다.

**하지 말 것:** 오답마다 정령의 소크라테스식 역질문을 붙이는 것. 기획서 2-4가 명시적으로 금지합니다 — 심층 역질문은 플레이어가 필드/메뉴에서 **직접 대화를 요청했을 때만** 발동합니다.

## 부록 A — 마일스톤별 "먼저 물어봐야 할 값"

CLAUDE.md 5장에 따라, 아래 값들은 **임의로 지어내지 않고 반드시 먼저 확인**합니다. 그 전까지는 ScriptableObject/`[SerializeField]`로 노출만 해두고 기본값은 명백한 임시값(예: 0 또는 주석 `// TODO: 미정`)으로 둡니다.
