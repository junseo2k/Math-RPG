## 1. 전제 [확정]

- 예측 대상 1단계는 **플레이어 미래 위치**, 행동 예측은 이후 별도 작업.
- 예측 실패도 정상 전투 결과로 취급하며, 적중하도록 보정하지 않는다.
- 모델 성능은 검증으로만 판단한다. 검증 전 모델을 완성된 AI로 표기하지 않는다.

### 1-1. 개인 행동 기억 [확정]
1. 예지 보스는 **플레이어 개인**의 행동을 예측한다.
2. **장기 기억**: 이전 판들의 행동 기록.
3. **단기 기억**: 현재 판의 행동 기록.
4. 플레이어의 현재 **스킬 빌드**에 따른 행동 차이를 고려한다.
5. 사망 시 장기 기억은 유지하고, 단기 기억은 초기화한다(세계관의 "시종은 이전 만남을 기억한다"와 일치).
- **[미결]** 장기·단기 기억을 GRU에 결합하는 구체적 방식.

## 2. 기술 조사 결과

| 항목 | 결과 |
|---|---|
| Unity | 6000.3.12f1 (6.3 LTS) |
| Unity Inference Engine(구 Sentis) | 2.3·2.6 모두 ONNX **GRU 미지원**(지원 목록 밖). LSTM은 CPU·GPUCompute 지원 |
| 결론 | `nn.GRU`를 ONNX로 그대로 내보내면 Unity에서 불러올 수 없음 |

- **[확정] 추론 방식 A**: 학습 가중치를 JSON으로 내보내고 C#에서 GRU 순전파를 직접 계산한다. 패키지를 추가하지 않는다.

## 3. 단계

| 단계 | 내용 | 위치 | 상태 |
|---|---|---|---|
| 1 | 데이터 수집 | `Assets/Scripts/Player/PlayerRecorder.cs` → `ML/data/raw/*.csv` | 구현 |
| 2 | 데이터셋 정의 | `ML/` (Python) | ⏸ 보류 |
| 3 | 학습·평가 | `ML/` (PyTorch) | ⏸ 보류 |
| 4 | Unity 연동 | C# GRU 추론 + 일치성 테스트 | ⏸ 보류 |

### 1단계: 데이터 수집 [확정]
- F9로 기록 시작/정지. 진행 중(Playing) 상태에서만 기록.
- 기본 간격 0.05초. 사망·스테이지 변경 시 파일(세션) 분리.
- 열: `t,x,y,vx,vy,grounded,facing,left,right,jump,attack,dash,has_boss,boss_dx,boss_dy,stage,day,hp`
- 입력 열은 직전 샘플 이후 한 번이라도 눌렸으면 1.
- 한계: 예지 보스가 없어 축적 보스전 등으로 대체한 데이터이고, 개발자 1인 플레이라 편향 가능. 결과 보고에 명시.
- 원본 CSV는 git에서 제외(`ML/data/`).

### 2단계: 데이터셋 정의 [제안]
- 입력: 최근 N개 샘플의 특징(보스 기준 상대 위치로 정규화).
- 정답: H초 뒤 **변위**(현재 위치 기준).
- 분할: **세션 단위** 학습/검증/테스트(구간 겹침에 의한 누수 방지).
- 실험 후보: 샘플 간격 0.05/0.1초, N 10~30, H 0.3/0.5/1.0초.

### 3단계: 학습·평가 [제안]
- 모델: GRU 1~2층 → 선형층 → (dx, dy). 구조·하이퍼파라미터는 검증 세트로 결정.
- 비교 기준: 정지, 등속 외삽.
- 지표: H초 뒤 위치 오차(평균·중앙값·90백분위), **적중률**(오차 < 예측 공격 반경), 추론 시간.
- 채택: 테스트 세션에서 등속 외삽보다 의미 있게 우수할 때. 기준값은 결과를 보고 사용자가 결정.

### 4단계: Unity 연동 [제안]
- C# GRU 순전파, 가중치 JSON 로드.
- 일치성 테스트: 같은 입력에서 PyTorch와 C# 출력 차이 1e-4 이내.
- 모델 없음·오류 시 등속 외삽으로 대체.

## 4. 미결

| 항목 | 결정 시점 |
|---|---|
| 시퀀스 길이 N, 샘플 간격, 예측 시점 H | 2~3단계 실험 |
| 수집할 데이터 양(목표 플레이 시간) | 2단계 전 |
| 채택 기준값 | 3단계 결과 후 |
| 예지 발동 간격, 예측 공격 범위, 보스 패턴 | 예지 보스 기획(planner) |
