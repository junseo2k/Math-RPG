# 게임 기획 개요 (Game Design Overview)

> 주제: 시간 / 장르: 로그라이크 / 엔진: Unity(C#) / 용도: 1인 개발 취업 포트폴리오

---

## 0. 문서 규칙

| 표기 | 뜻 |
|---|---|
| **[확정]** | 사용자가 확정한 규칙. 변경 시 사용자 승인 필요 |
| **[제안]** | 기획 담당의 해석·제안. 승인 전까지 확정 아님 |
| **[미결]** | 아직 정하지 않은 사항. 11장 목록에서 관리 |

- 세계관(설정)과 플레이 규칙(실제 게임 동작)은 항목을 나눠 적는다.
- 수치는 이 문서에서 정하지 않는다. 조절 대상은 12장에 항목만 기록한다.

## 1. 프로젝트 방향 [확정]

- Unity/C# 기반 로그라이크.
- 취업용 1인 개발 포트폴리오.
- 한 판마다 구성이 달라지고, 사망하면 새로운 판을 시작한다.
- 시간은 배경 설정뿐 아니라 **게임플레이의 핵심 규칙**이다.
- 시험판(vertical slice)을 먼저 완성하고 본편으로 확장한다.

**기획 의도**: "시간 = 메커닉"을 보스·권능·반복 구조 전반에 일관되게 적용해 포트폴리오의 차별점으로 삼는다. 시험판 우선은 1인 개발 범위를 통제하기 위함이다.

---

## 2. 세계관 (설정)

### 2-1. 핵심 설정 [확정]

- 주인공은 **몰락한 태양신**이다.
- 태양신의 본질적인 권능은 **시간의 흐름**이다.
- **달의 시종 12명**이 반역을 일으켰다.
- 시종들은 **영원히 변하지 않는 상태**를 최고의 가치로 여긴다.
- 시종들은 달을 영원히 바라보기 위해 **영원한 밤**을 만들고자 한다.
- 달은 상대적으로 수동적인 존재다.
- 시종들의 시간 권능은 태양신에게서 빼앗은 조각이 아니라 **각자가 가진 고유한 권능**이다.

**기획 의도**: "흐름(태양신)"과 "불변(시종)"의 대립으로 갈등 축을 단순하게 세운다. 시종의 권능을 고유한 것으로 두어, 각 시종이 독립된 개성과 동기를 갖게 한다.

### 2-2. 모티브와 독자 해석 구분 [확정]

| 구분 | 내용 |
|---|---|
| 실제 신화(모티브) | 이집트 신화, 특히 **암두아트**: 태양신이 밤의 12시간을 지나 새벽에 다시 떠오르는 여정 |
| 게임 독자 해석 | 달의 시종 12명의 반역, 시간 권능 체계, 영원한 밤, 시간 순서 왜곡, 태양신의 사망과 재탄생 규칙 |

- 문서·게임 내 텍스트에서 실제 신화와 게임 설정을 혼동하지 않도록 구분한다.

## 3. 시간 구조

### 3-1. 설정 [확정]

- 세계는 **18:00부터 다음 날 06:00까지** 진행한다.
- 왜곡된 세계에서는 06:00 이후 다시 18:00이 온다.
- 이것은 세계 전체의 초기화가 **아니다**. NPC와 세계의 기억 및 역사는 유지된다.
- **최종 시종**이 시간의 연결 순서를 바꾸어 영원한 밤을 유지한다.

### 3-2. 플레이 규칙 [확정]

- 시간은 현실의 초 단위가 아니라 **스테이지 진행에 따라 전진**한다.

**기획 의도**: 실시간 타이머의 압박 대신, 진행 = 시간 경과로 만들어 플레이어가 현재 위치(몇 시)를 여정의 진척도로 읽게 한다.

### 3-3. 미결
- 스테이지 1개당 전진하는 게임 내 시간
- 시간대(시각)가 스테이지 구성·적·보상에 주는 영향 여부

---

## 4. 로그라이크 반복 (사망과 재탄생)

### 4-1. 설정 [확정]

- 태양신은 죽으면 **다음 날 18:00에 재탄생**한다.
- 사망은 **시간 역행이 아니다**.
- 시종들은 죽지 않으며 **이전 만남을 기억**한다.

### 4-2. 플레이 규칙 [확정]

| 유지 | 초기화 |
|---|---|
| 플레이어의 기억 | 스테이지 진행 |
| 세계(NPC)의 기억과 역사 | 임시 권능 |
| 여정에서 얻은 영구 성장 | 장비 |
| 시종의 기억 | 전투 능력치 |

**기획 의도**: 반복을 "되감기"가 아닌 "다음 날"로 표현해, 회차가 쌓일수록 세계와 시종의 반응이 달라지는 이야기 장치로 활용한다. 영구 성장은 반복 플레이의 동기를 유지한다.

### 4-3. 미결
- 영구 성장의 종류와 획득 방식
- 시종의 기억이 대사·패턴에 반영되는 방식과 범위

---

## 5. 챕터와 12시종 권능

### 5-1. 챕터 구성 [확정]

| 장 | 이름 | 시간대 | 권능 | 핵심 권능 |
|---|---|---|---|---|
| 1장 | 탄생 | 18:00~21:00 | 시간 축적 · 시간 유예 · 시간 역행 | **역행** |
| 2장 | 존재 | 21:00~00:00 | 시간 감속 · 시간 공유 · 시간 정지 | **정지** |
| 3장 | 쇠퇴 | 00:00~03:00 | 시간 침식 · 시간 갱신 · 시간 가속 | **가속** |
| 4장 | 종언 | 03:00~06:00 | 시간 분기 · 시간 예지 · 시간 순서 | **순서** |

- 시종 12명은 각자 고유한 권능을 하나씩 가진다(12명 = 12권능).
- 3장과 4장의 개별 권능 **시간 배치는 미확정**이다. 위 표의 3·4장 권능 나열 순서는 배치 순서를 뜻하지 않는다.

### 5-2. 권능 획득 [확정]

- 플레이어는 시종을 쓰러뜨리면 그 시종의 권능을 **임시 권능**으로 얻는다.
- 임시 권능은 사망 시 초기화된다(4-2).

**기획 의도**: 장 이름(탄생→존재→쇠퇴→종언)이 태양신의 하루이자 생애를 따라간다. 적의 권능을 그 판 동안 빌려 쓰는 구조로, 판마다 권능 조합이 달라지는 로그라이크 변주를 만든다.

### 5-3. 챕터 내부 구조 [확정]

- 시종 보스 1명에 도달하기까지 **일반 방 2개**를 거친다.
- 한 챕터 = (일반 방 2 + 보스 방 1) × 3 = **스테이지 9개**.

```
일반 → 일반 → 보스1 → 일반 → 일반 → 보스2 → 일반 → 일반 → 보스3
```

### 5-4. 챕터 종료 보상 [미결]

- 챕터를 마칠 때마다 시간 권능을 강탈하는 **특수한 시간 능력**을 넣을 예정이다.
- 내용은 미정이며, 시험판에서는 구현·테스트하지 않는다.

### 5-5. 제안
- **[제안]** 시종 1명이 1시간을 담당한다(18:00~06:00 = 12시간 = 12시종). 5-3 구조에서 일반 방 2 + 보스 방 1 = 1시간이 된다.

### 5-6. 미결
- 챕터 종료 특수 시간 능력의 내용(5-4)
- 일반 방의 내용(적 구성, 보상 유무)
- 3·4장 권능의 시간 배치
- 시종별 이름, 외형, 성격
- "핵심 권능"의 게임 내 의미(장 보스 지정, 획득 보장 여부 등)
- 임시 권능의 사용 방식(액티브/패시브, 장착 개수 제한 등)
- 같은 판에서 권능을 몇 개까지 얻을 수 있는지

## 6. 보스

### 6-1. 특수 보스 [확정]

**시간 분기 보스**
- 복수의 가능한 미래를 다루는 콘셉트.

**시간 예지 보스**
- 다른 보스와 차별화해 **GRU 기반 예측 AI**를 사용한다. (상세: 7장)

**최종보스 (시간 순서)**
- 시간 순서를 조작하며, **원인과 결과의 발생 순서를 뒤바꾼다**.
- **결과 확정형**과 **결과 예약형** 패턴을 모두 사용한다.
- 인과 역전으로 체력이 0이 되어도, **원인을 저지할 기회가 끝날 때까지 사망 판정을 유예**한다.

**기획 의도**: 마지막 장의 보스들은 "미래(분기·예지)"와 "인과(순서)"를 다뤄, 앞 장에서 익힌 시간 권능을 종합하는 보스전이 되게 한다.

### 6-2. 시종 보스 패턴 원칙 [확정]
- 각 시종 보스는 **자신의 고유 권능을 그대로 사용하는 패턴**으로 구현한다. (예: 역행 보스는 시간 역행을 쓴다)

### 6-3. 미결
- 각 시종 보스의 구체 패턴(권능을 어떤 공격·기믹으로 쓰는지)
- 분기 보스의 구체 패턴
- 결과 확정형/예약형 패턴의 구체 내용
- 모든 보스 수치

## 7. AI (시간 예지 보스)

> **⏸ 개발 보류 (2026-10-15)**: 시험판 완성을 우선한다. 재개 조건·상세는 `Docs/ForesightAI.md` 0장.

### 7-1. 확정 [확정]

- 플레이어 **개인**의 행동을 예측한다.
- **장기 기억**(이전 판들의 행동)과 **단기 기억**(현재 판의 행동)을 활용하며, 현재 **스킬 빌드**에 따른 행동 차이를 고려한다.
- 사망 시 장기 기억은 유지하고 단기 기억은 초기화한다.
- 1단계: **미래 위치 예측**을 먼저 구현한다.
- 2단계: 이후 **다음 행동 예측**을 추가한다.
- 예측 모델은 충분한 실험과 평가를 거쳐 사용한다.

**기획 의도**: "미래를 보는 보스"를 연출이 아닌 실제 플레이어 데이터 기반 예측으로 구현해, 포트폴리오에서 AI 활용 역량을 함께 보여준다.

### 7-2. 제안
- **[제안]** 평가 항목: 예측 오차, 추론 지연(ms), 플레이어 체감 난이도
- **[제안]** 모델 실패·지연 시 사용할 기본(규칙 기반) AI를 대체 수단으로 둔다.

### 7-3. 미결
- 장기·단기 기억을 GRU에 결합하는 방식
- 사용 합격 기준 수치
- (결정됨: 데이터 수집 = PlayerRecorder, Unity 연동 = C# 직접 구현. `Docs/ForesightAI.md`)
- 예측 결과를 보스 패턴에 반영하는 방식

## 8. 플레이어와 보상

### 8-1. 확정 [확정]

- 전투 방식은 **2D 횡스크롤**이다.
- 주인공의 기본 무기는 **검**이다.
- 이집트 신화의 신성한 도구를 모티브로 한 **희귀 무기**를 등장시킨다.
  - 신성 도구의 **의미(상징·역할)만** 가져오고, **외형은 중세풍**으로 해석한다. (이집트 신화는 서사에만 쓰고 시각은 중세풍이라는 원칙, ArtSpecification 1-1)
- 희귀 무기는 **확률적으로** 획득할 수 있다.
- 우선 **챕터 보상**으로 배치하는 방향을 사용한다.

### 8-2. 미결
- 조작 세부(이동·점프·공격·회피 등 행동 목록과 입력)
- 희귀 무기 목록과 세부 효과
- 보상 종류와 확률

## 9. 시작 능력

### 9-1. 확정 [확정]

- 후보는 총 **10개**이며 액티브와 패시브를 혼합한다.
- 플레이어는 게임에 **먼저 진입**한다.
- 시작 지점에서 후보 10개 중 **중복 없이 3개**를 무작위로 제시한다.
- 플레이어는 그중 **1개만** 선택하고 진행한다.

**기획 의도**: 시작부터 선택지를 줘 판마다 출발점을 다르게 하고, 3개 중 1개로 선택 부담을 줄여 처음 하는 플레이어도 쉽게 고를 수 있게 한다.

### 9-2. 시험판 적용 [확정]
- 시험판에는 **임시 능력 3개만** 넣는다. 후보가 3개이므로 3개가 모두 제시되고, 그중 1개를 선택한다.
- 임시 능력 3개는 정식 10개와 별개인 시험용이다.

### 9-3. 미결
- 정식 10개 능력의 이름과 실제 효과
- 시험판용 임시 능력 3개의 내용
- 이전에 제안된 능력 목록은 확정 사항으로 사용하지 않는다.

## 10. 시험판 범위

### 10-1. 포함 [확정]
- 2D 횡스크롤 전투(기본 무기: 검)
- 1장(탄생) 18:00~21:00, 스테이지 9개(5-3 구조)
- 시종 보스 3명(축적·유예·역행), 각자 고유 권능 기반 패턴
- 시작 능력 선택(임시 능력 3개 중 1개)

### 10-2. 제외 [확정]
- 챕터 종료 특수 시간 능력(5-4)

- 보스 처치 시 임시 권능 획득(5-2), 영구 성장, 저장, 희귀 무기, 시종 재회 반응

### 10-3. 시험판 세부 [확정]
- 사망 → 다음 날 18:00 재탄생(영구 성장 없이 전부 초기화)
- 플레이어 행동: 이동·점프·검 공격·대시
- 일반 방: 적 전멸 시 출구 개방

상세: `Docs/VerticalSliceSpec.md`
