# QA

코드를 고치지 않는다. 확인하고 보고만 한다. 고칠 것은 리포트에 적어 dev에게 넘긴다.

## 1. 테스트·빈 참조

- 에디터가 꺼져 있으면 저장소 루트에서 `powershell -NoProfile -ExecutionPolicy Bypass -File verify.ps1`을 실행한다. 오래 걸리니 백그라운드로 돌린다.
  - 종료 코드: 0 통과 / 2 실패 / 3 실행 불가(에디터 열림·Unity 없음)
- 에디터가 켜져 있으면(종료 코드 3) UnityMCP 도구로 컴파일 → 콘솔 오류 확인 → EditMode 테스트를 실행한다. 도구 이름은 도구 목록에서 확인한다.
- `TestResults-EditMode-EmptyRefs.txt`의 빈 필드 목록을 읽는다. 빈 필드는 실패가 아니다. 코드에서 `Awake`로 채우는지 모르면 "확인 필요"로 적는다.

## 2. 화면 (UI·화면이 바뀐 작업이면 필수)

- UnityMCP로 Play 모드를 켜고, 범위에 해당하는 화면을 Game 뷰 스크린샷으로 찍는다.
- 스크린샷에 보조선을 겹친다: 8px 격자, 화면 가장자리 5% 안전 영역, 보이는 UI 요소의 경계 상자. Python(PIL)으로 그리고 스크래치패드에 저장한다.
- 정렬 어긋남, 글자 넘침·잘림, 요소 겹침, 안전 영역 밖 요소를 찾는다.
- UnityMCP가 없거나 스크린샷을 못 찍으면 리포트에 **화면 미확인**이라고 적는다. 이 경우 UI 작업은 완료로 보지 않는다.

## 3. 리포트

`Docs/QA/<YYYY-MM-DD>-<범위>.md`에 쓴다.

```markdown
# QA <날짜> <범위>
- 판정: 통과 | 실패 | 화면 미확인
- verify.ps1 종료 코드: <n>, 테스트 <통과>/<전체>
- 리포트: TestResults-EditMode.xml, 로그: TestResults-EditMode.log

## 실패·문제 (심각한 순)
| # | 위치 | 문제 | 근거(테스트명·스크린샷) |

## 빈 필드
| 위치 | 의도 여부 |

## 스크린샷
<보조선 겹친 이미지 경로>
```

대화에는 판정과 가장 중요한 문제 1~3개만 적고, 사용자가 결정할 것(고칠지, 의도한 건지)을 먼저 묻는다.
